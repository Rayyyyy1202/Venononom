# GWM EU Homepage Demo + AI Chatbot Widget

A self-contained internal demo: a local mirror of [gwm-eu.com/eu](https://www.gwm-eu.com/eu)
with an AI chat widget grafted onto it. The widget talks to a small FastAPI
backend that proxies to OpenAI (default model: `gpt-5.4`, configurable).

## Local quick start

```bash
# 1. Scraper deps + scrape the homepage (one-time; public/ is already in git)
pip install requests beautifulsoup4
python3 scripts/scrape.py

# 2. Backend deps
pip install -r server/requirements.txt

# 3. Configure OpenAI
cp .env.example .env
$EDITOR .env        # set OPENAI_API_KEY (and OPENAI_MODEL to override)

# 4. Run
./run.sh            # http://localhost:8000
```

Open <http://localhost:8000>. The page renders identically to the live site,
plus a small red AI chat button in the bottom-right corner.

## Deploy to Vercel (public URL, anyone can use it)

The repo is Vercel-ready: `public/` is the static root, `api/index.py` exposes
the FastAPI chat endpoint as a Vercel Python serverless function, and
`vercel.json` wires `/api/*` to the function while everything else is served
straight from `public/`.

### Option 1: GitHub integration (no CLI)

1. Sign in at <https://vercel.com> with GitHub
2. **Add New… → Project** → import `Rayyyyy1202/Venononom`
3. Framework preset: **Other** (Vercel auto-detects `vercel.json`)
4. **Environment Variables** (Settings → Environment Variables):
   - `OPENAI_API_KEY` = your real key
   - `OPENAI_MODEL` = `gpt-5.4` (or whatever your account has)
5. Click **Deploy** — done. URL: `https://<project>.vercel.app`

Every push to the deploy branch auto-redeploys.

### Option 2: CLI

```bash
npm i -g vercel
vercel login
vercel --prod
# answer prompts; project links to your account

# Set secrets (or use the dashboard)
vercel env add OPENAI_API_KEY production
vercel env add OPENAI_MODEL production
vercel --prod                  # redeploy with the new env
```

### After deploy

- Health check: `https://<project>.vercel.app/api/health`
- Open root, click the chat button, ask a question — the widget calls
  `/api/chat` on the same origin so no CORS setup is needed.

If you see "model_not_found" errors in the chat panel, change `OPENAI_MODEL`
in Vercel's env vars to a model your key has access to (e.g. `gpt-4o-mini`)
and redeploy.

## How it works

```
┌────────────────────┐   POST /api/chat (SSE)   ┌──────────────────┐
│  chatbot.js (UI)   │ ───────────────────────► │  FastAPI app     │
│  in scraped page   │                          │  server/main.py  │
└────────────────────┘ ◄──── token stream ──────└────────┬─────────┘
                                                          │ knowledge.json
                                                          ▼ as system prompt
                                                  ┌────────────────────┐
                                                  │  OpenAI Chat API   │
                                                  │  (gpt-5.4 default) │
                                                  └────────────────────┘
```

- **System prompt** is built from `chatbot/knowledge.json` so the bot stays
  on-topic about GWM Europe (models, dealers, warranty, contact).
- **Streaming** via SSE: tokens render in the chat bubble as they arrive.
- **No mock fallback** — if OpenAI fails, the widget shows a single graceful
  error bubble with a link to `info@gwm-eu.com`.

## Configuration

| Variable | Default | Notes |
|---|---|---|
| `OPENAI_API_KEY` | (required) | Your OpenAI key |
| `OPENAI_MODEL` | `gpt-5.4` | Override if your account doesn't have access — e.g. `gpt-4o-mini` |
| `OPENAI_BASE_URL` | (unset) | For Azure OpenAI / OpenRouter / Ollama / local proxies |

Locally: edit `.env`. On Vercel: Settings → Environment Variables.

Health check: `curl http://localhost:8000/api/health`
→ `{ok, model, has_key, kb_loaded}`.

## Re-running the scraper

```bash
rm -rf public/ && python3 scripts/scrape.py
```

The scraper:
- Downloads the `/eu` homepage + 77 same-origin assets (CSS, JS, fonts, images, videos)
- Strips Google Tag Manager / Analytics scripts and their `<noscript>` fallback
- Catches AEM `data-src-pc/mob`, `data-poster-pc/mob`, `data-special-poster` lazy attrs
- Scans downloaded JS/CSS for `/content/dam/gwm/...` paths Vue `:src` bindings reference
- Hard-lists template-built paths (hero swiper PNG sequences, header logos)
- Injects `<link>`/`<script>` tags for the chatbot widget into `</body>`

## Limitations

- Only the **English EU homepage** (`/eu`) is mirrored. Internal links to
  unscraped pages (`/eu/models/h7` etc.) are neutered to `#`.
- Cookie-banner SDKs (OneTrust) and analytics RUM are blocked locally — they
  only run on the live origin. This is fine for the demo.
- Newsletter / contact forms (none on the homepage anyway) won't submit.
- Vercel Hobby tier function timeout is 60s — fine for typical chat
  responses; bump to Pro if you need longer streams.
